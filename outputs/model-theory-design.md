# Deductrium 推理层模型论玩法：精简实现方案

版本：2.0（按 2026-11-09 的精简意见修订）  
范围：只添加推理层玩法；本文不代表功能已经实现。  
实现状态：已在本地 `feature/model-theory` 开始首阶段开发，实际支持范围与未完成内容见 `MODEL-THEORY.md`；本文仍是完整目标，不代表全部功能已完成。按用户授权分阶段创建本地提交，暂不推送。

## 2. 数学目标和边界

研究谓词论域下的集合论：`M = <D, ∈|D>`。相等与属于关系沿用外层集合论关系。论域可为集合大小，也可为可定义真类。

实现公式相对化、项的内部解释、绝对性及公式结构归纳，使玩家能够在现有推理层中证明候选论域满足或违反 ZF/ZFC 的公理及公理模式。

不实现独立模型层、统一对象层满足关系、任意关系的模型编辑器、公式集合编码、自动判定模型是否满足 ZF。

不赠送“任何模型满足 ZF”之类数学结论。构造模型、证明所需公理仍由玩家完成。

## 3. 当前代码事实：如何尽量复用

- `mprd` 在 `src/fs/formalsystem.ts::metaNewVerb` 中生成 `dv<name>`。形式参数、定义体已经在规则 AST 内，无需再保存一份。
- `mf` 在 `metaNewFunction` 中生成 `df<name>`；本质是满足存在条件后选取一个值的定义模式，不要求关系唯一。
- `mc` 的实际规则前缀是 `dc<name>`，也应纳入“生成相对化定义”的支持范围。
- `AssertionSystem.match` 目前只把替换变量节点当通配符，调用名和节点数量默认要求一致。谓词名和列表模板需要新增专门分支。
- `ASTMgr.replaceByMatchTable` 不会替换调用名，不能直接承担谓词名绑定。
- `##matchrp` 目前出现在 `initial.ts` 的元规则说明中；实际 `mifft` 执行走 `cmd.ts` 的 `ifft` 分支及 `metaIffTheorem`，内部调用 `matchSubAndReplace` 等代码。它不是已经存在的通用元程序解释器。
- `metaIffTheorem` 中的递归证明生成可以借鉴，但新直接展开模式不要求玩家手动使用它。
- `entr` 和 `inln` 已是查看/展开宏，不改变这两个命令原有含义。
- 网页直接加载 `js/`，未来实现时须正常编译 TS，并同步 JS/source map。

不新建完整的模型论子系统。建议最多新增 `src/fs/model.ts`，承载纯变换、定义分析和直接推理辅助；其余修改进入已有解析、匹配、命令、界面与证明逻辑。

## 4. 谓词符号模板：实时查找，不保存副本

### 4.1 输入

```text
"c(x)
"r(x,y)
"p($x,...$args)
```

ASCII 双引号是单个前缀，不是成对引号。`"c` 匹配的是经 `mprd` 定义的谓词符号，不是任意公式文本。

例如 `"r($x,$y)` 匹配 `r(a,b)` 时，本次推理得到 `"r -> r`、`$x -> a`、`$y -> b`。

### 4.2 临时定义读取

```ts
inspectPredicateDefinition(fs, name): {
    parameters: AST[];
    body: AST;
    definitionRuleId: string;
}
```

读取现有 `dv<name>`，剥离其正式参数量词并识别定义等价式。核对实际谓词名、元数、形式参数和主体。若无法可靠识别，拒绝本次操作，不靠名称猜测。

这只是一次调用内的临时分析对象，不是新注册表，也不需要保存到存档。修改、删除定义后的下一次调用重新读取，不依赖过期信息。

也可用一次操作内的临时 Map 去重读取；操作完成后丢弃。无需持久化 fingerprint、签名数据库或模型参数数据库。

### 4.3 动态长度参数列表

使用 `...$args` 表示一段项参数列表，不是单个项，也不是普通公式变量。首版只支持每个调用末尾一个列表模板，避免复杂的多段列表切分匹配。

```text
"p(...$args)
"p($x,...$args)
```

匹配具体谓词时，由目标实参数列确定列表长度，并与它的 `dvxx` 定义核对。`"p($x,...$args)` 的总元数为 `1 + len($args)`。

证明通用规则期间可以保留未定长度，不必先写死一元/二元。要求所有推理步骤对列表整体成立；不能只验证某个长度的实例，就声称支持任意长度。

本次实例化中：同一个列表模板必须绑定同一有序 AST 列表；同一个谓词模板必须绑定同一谓词符号和同一实际元数。不同次实例化可以绑定不同元数的谓词。

不增加“同一个具体谓词具有任意元数”的语义，也不自动支持动态量词列表。若证明需要逐参数构造过程，必须由内置推理辅助在实际列表长度确定后生成相应步骤。

### 4.4 绑定范围

表达式绑定、谓词名绑定、参数列表绑定均为单次规则应用的临时状态。录制宏保存的是带模板的规则或实际证明步骤，不保存全局“当前 c 是谁”。

引用一个具体谓词时，规则和宏本身保留该符号的依赖。删除被引用规则时仍沿用已有依赖保护。

## 5. 不使用 `#dom`：论域参数直接写 D

公开形式：

```text
#sat(A,"c)
#sat(t,"c)
#abs(A,"c)
#abs(t,"c)
```

此处裸 `"c` 是论域谓词引用；作为域使用时必须具有一个元素输入位置。

具体实例化后可使用已定义的一元谓词名，例如 `#sat(A,m)`。

若域谓词带固定参数，采用下面的局部模板形式：

```text
#sat(A,m(_,a,b))
#sat(A,"c(_,a,b))
#sat(A,"c(_,...$params))
```

`_` 仅在第二参数最外层谓词调用中表示论域元素槽。第一版要求它出现在首参数位置且恰好一个；其余参数固定。例如 `m(_,a,b)` 代表 `x |-> m(x,a,b)`。

`_` 不是新的一阶数学对象，也不在其他普通表达式中全局改义。该语法只由 `#sat/#abs` 的第二参数解析辅助处理。

这仍然是 `#sat(t,D)` 两个参数，不新增用户可见的 `#dom` 构造。内部可以用临时 `DomainView {predicateName, fixedArguments}` 表示解析结果，但不需要独立的公开 AST 对象或存档条目。

一般的多元谓词模板与作为论域的一元模板是两个用途：前者可匹配任意元数；后者需要留出且只留出一个元素槽。

## 6. 双参数 `#sat` 的类别

| 输入 | 结果类别 | 用途 |
|---|---|---|
| `#sat(A,D)`，A 是公式 | 公式 | 公式在 D 中的相对化 |
| `#sat(t,D)`，t 是项 | 项 | t 的模型内部解释 |
| `#abs(A,D)`，A 是公式 | 公式 | A 在 D 下的绝对性命题 |
| `#abs(t,D)`，t 是项 | 公式 | t 的内部解释与外部值一致的命题 |

删除上一版 `#sat(t,z,D)` 公共接口，不另做“内部项值登记”。

`#sat` 的输出类型与第一个参数相同，纳入已有的项/公式类型约束传播。`#abs` 的输出总是公式，首参数类型由上下文、具体结构或输入时选择确定；若完全无法确定，报类别歧义，不猜测。

必要时保留 `#abst/#absf` 作为消歧输入和规范打印别名，解析后仍是同一种系统操作的两种类型实例。目的是让字符串存档往返保留类别，不增加数学功能。

节点可继续使用 `fn` 及保留名字 `#sat/#abs`，加必要的类别辅助信息；不必为了这个功能重构所有旧 AST。所有克隆、替换、打印操作都要保留该类别。第二参数按谓词引用/域模板检查，不能默认作为普通项。

## 7. 默认不规约，允许有限嵌套

解析、匹配、显示、录制宏和存档不自动展开 `#sat/#abs`。已有 `AssertionSystem.expand` 不能把它们当作需要立即执行的 `#rp`。

但仍需处理类型、自由变量、替换和不自由出现断言。“不规约”不是“不检查内部”。

允许：

```text
#sat(#sat(A,D1),D2)
#abs(#sat(A,D1),D2)
#sat(#absf(A,D1),D2)
```

嵌套解释为先展开内层含义，再在外层相对化。不能无条件抹去内层，也不把两个论域简单合并为交集。

如果定义中间接引用自身而造成无限展开，本次展开检测递归栈并拒绝；不增加持久化定义依赖图。设置合理的单次展开预算，超限回滚。

## 8. 公式的一层展开规则与内部开关

以下用 `D(x)` 简写将 x 填入域模板。A、B 可以继续包含未展开的模型操作。

```text
#sat(x@y,D)  -> x@y
#sat(x=y,D)  -> x=y
#sat(~A,D)   -> ~#sat(A,D)
#sat(A>B,D)  -> (#sat(A,D)>#sat(B,D))
#sat(Vx:A,D) -> Vx:(D(x)>#sat(A,D))
#sat(Ex:A,D) -> Ex:(D(x)&#sat(A,D))
```

此处箭头是“展开结果”说明，不表示自动赠送一条对象语言蕴含公理。

包含常量/函数的原子公式可生成项解释，例：

```text
#sat(t@u,D) -> #sat(t,D)@#sat(u,D)
#sat(t=u,D) -> #sat(t,D)=#sat(u,D)
```

当 t/u 是变量时，项相对化保留该变量；当它们为构造项时，保留对应不透明项解释，按第 10 节使用相对化定义。

当前相对化所插入的 D(x) 保持当前域的外层含义，不再次递归相对化自己。卫生改名保证原公式量词不会意外捕获域的固定参数。

增加内部配置，不做 UI 开关或生存模式解锁：

```ts
const modelSyntaxOptions = {
    unfoldAnd: true,
    unfoldOr: true,
    unfoldIff: true,
    unfoldExists: true,
};
```

四个开关分别控制 `#sat(A&B,D)`、`#sat(A|B,D)`、`#sat(A<>B,D)`、`#sat(Ex:A,D)` 的直接展开行动，默认全部开启。前三项展开为对两个子公式分别相对化后使用原连接词；存在量词 E 展开为 `Ex:(D(x)&#sat(A,D))`。

`unfoldExists` 独立控制 E 的这一层直接展开。关闭时不暗中先把 E 转成否定与全称再展开；用户仍可用已有的存在量词定义自行转换。关闭 `unfoldAnd` 不妨碍已开启的 E 展开生成 `&`，因为开关控制的是目标节点的直接展开入口，不是禁止结果中出现某个符号。

关闭时提示该直接操作暂不可用；不改变连接词含义，不把表达式当作未解释原子，也不修改已有证明的数学结果。已有证明/宏重放应使用录制时明确的合法规则，不因为以后关闭一个玩法入口而失效。

`E!` 等其他语法只在已有可靠展开规则时支持；暂不支持时给出明确提示，不顺带扩大实现范围。

## 9. 新的直接展开推理模式

### 9.1 指令与按钮

```text
sat-expand p3 2    // 仅编号 #sat
abs-expand p3 1    // 仅编号 #abs
unfold p3 2        // 混合编号 #sat/#abs
unfold p3          // 选择 p3 中的目标
unfold            // 先选择定理，再选择节点
```

分别增加 `展开公式(unfold)`、`展开 sat(sat-expand)`、`展开 abs(abs-expand)` 按钮。所有入口默认解锁，具体映射见第 14 节。按钮进入对应计数类型的独立选择模式，不改变普通点击插入、复制、拖动的功能。Esc 取消。

### 9.2 编号与结果

对执行前源定理 AST 按先序遍历编号，外层先于内层；不展开定义去寻找隐含节点。本次行动只展开一个节点一层，新定理重新编号。

保留源定理，直接追加展开后的新定理并记录推理来源。玩家不需要先生成 `A<>B`，也不需要手动将等价传递到内部。

这是新的内置推理模式：核心检查目标节点、定义展开、变量作用域和上下文合法性后，直接接受这一条有依据的派生步骤。可以在内部调用现有证明辅助，也可以使用受限的定义展开检查器；不要求为每次行动生成并展示一长串 `<>` 传递。

### 9.3 必须保留的可靠性限制

“省去手动传递”不等于允许任意替换。

- 通过普通逻辑连接词、量词的定义展开，检查相应作用域。
- 在外层 `#sat/#abs` 内展开内层操作，仅允许符合已定义嵌套语义的转换。
- 不能仅从外部 `⊢ A<>B` 就无条件得到 `⊢ #sat(A,D)<>#sat(B,D)`；外部证明可能使用 D 不满足的公理。
- 用户的任意化简引理，仍须满足其前提；本模式只自动处理系统已支持的定义展开。

例如内层 `#sat` 的定义展开可直接在外层上下文内执行，但“把外部证明了的 ZF 公理替换为真”不能借此搬入任意域。

### 9.4 项节点的展开

项不能被直接替换成公式。因此选中项值 `#sat(t,D)` 时：

- 若存在明确的定义等式或已证明的绝对性等式，可按该依据得到新的源定理；
- 若只有一个存在条件下的定义性质，不把该性质当作项替入源公式；引导使用“生成相对化定义”行动，并保留其前提；
- 不以“展开”为名无条件断言内部值满足性质。

原子性执行：任一步失败都恢复源状态，不留下半条定理、临时假设或部分定义。

## 10. 点击生成 df/dv/dc 的相对化版本

### 10.1 功能

在已有 `dfxx/dvxx/dcxx` 定义条目上提供“生成相对化定义”操作。用户选择论域 D 后，产生普通定义规则；不登记一个模型对象。

指令建议：

```text
sat-def <definition-rule> <D>
```

复杂参数沿用现有命令分步输入，不能直接按空格拆整个公式。

除定义条目上的操作外，推理层工具栏必须有 `相对化定义(sat-def)` 按钮。点击后依次选择原定义、输入或选择论域、指定生成规则的位置/名称（若原有流程需要），然后调用与命令相同的实现。不能仅依赖条目悬停菜单或玩家手动输入 `sat-def`。

定义信息实时从原规则 AST 分析，不修改 `mprd/mf/mc` 的保存格式。操作内暂存原形式参数和主体即可。

按钮可以对定义条目统一显示，但必须识别合法定义模式。仅以名字开头为 df/dv 不能证明它确实是定义；无法识别的内置或用户规则应报告不支持，不能对任意同名前缀规则生成新公理。

### 10.2 关键：使用新的内部解释

不能把旧规则“在外部成立”当作其任意相对化版本的证明。正确方式是使用原有定义元规则，引入新的内部解释符号，并为它建立相对化的定义。

内部使用一个新普通谓词、函数或常量作为别名；`#sat` 与这个别名之间的联系是系统受限的解释约定，不是玩家可以任意指定的等式。

别名及其定义按普通自定义内容保存。无需再存一份映射表：从现有相对化定义规则中查找、核验即可。自动名字可按原符号、域谓词和参数槽结构生成，并检查冲突；不同固定参数值应作为别名的实际实参，而不是被错误当成一个不依赖参数的常量。

同一个原符号与同一个域模板对应稳定的内部解释，不能每次点击都重新选择一个值。已存在对应定义时复用；发现已有不兼容解释时拒绝重定义。新增定义须遵守原有新符号条件，不能通过给旧符号改义来改变此前证明的含义。相关检查直接查现有规则和引用，不要求新建持久化注册表。

### 10.3 谓词：复用 mprd

原定义示意：

```text
∀args: (p(args) <> R(args))
```

为新的内部谓词 p_D 通过 mprd 生成：

```text
∀params,args: (p_D(params,args) <> #sat(R(args),D_params))
```

相对化解释 `#sat(p(args),D)` 按规则联系到内部谓词；实际项参数先按需要相对化。域条件及变量约束须保持，不能把定义体的外部参数意外约束进内部。

可以用这条定义继续游玩、化简或录制推理规则。不同域不复用同一个不带域参数的内部谓词。

### 10.4 常量和函数：复用 mc/mf，不要求唯一性

原常量定义模式：

```text
(∃z R(z)) > R(c)
```

为新内部常量 c_D，mc 可给出：

```text
先构造 R_D(z) := #sat(R(z),D)
(∃z (D(z) & R_D(z)))
  > (D(c_D) & R_D(c_D))
```

这里的 `R_D` 只是本说明中的公式模板记号，不增加游戏谓词。`R_D(c_D)` 表示先相对化含变量 z 的 R，再将内部值 c_D 自由代入结果；不能写成先把 c_D 填入 R 再重新对其相对化，否则会把已经得到的内部值再次内部解释。

没有内部见证存在性时，不得到右侧性质。非唯一不构成错误：c_D 只是原定义机制允许的一个新选择值。

若 D 带固定参数，内部“常量”实际上依赖这些参数，须通过 mf 引入对应参数函数，不能误用一个全局固定的 mc 常量。

原函数定义模式示意：

```text
(∀x ∃z R(x,z)) > ∀x R(x,f(x))
```

对内部定义，先设：

```text
R_D(x,z) := #sat(R(x,z),D)
S_D(x,z) := D(x) > (D(z) & R_D(x,z))
```

通过现有 mf 为新函数 f_D 生成：

```text
(∀x ∃z S_D(x,z)) > ∀x S_D(x,f_D(x))
```

这是合法的新定义，不要求 R 唯一。需要时再用普通逻辑把前提整理为：

```text
∀x (D(x) > ∃z (D(z) & R_D(x,z)))
```

`S_D(x,f_D(x))` 同样是在已经相对化的定义体中代入内部函数值，不再对 f_D(x) 做第二次解释。

多元时将 D(x) 换为所有对象输入属于域的合取；域固定参数是外部参数，作为新定义的额外正式参数处理，不自动要求它们属于 D。

不能直接保留原 f 再给它追加更强的内部性质；也不能省去上述存在前提。这两点是即使用户不关心选择唯一性，也必须保留的防矛盾条件。

用户最终使用的项记法仍是 `#sat(f(t),D)`，不是上一版的三参数性质接口。定义性质是通过本行动产生的普通公式，可以继续推理。

### 10.5 内置项和未知定义

纯变量的项相对化是自身。其他内置常量、构造符号只有在能从已有定义可靠识别其定义模式时才生成内部版本；本次不额外添加任何具体符号的数学定理。

尤其不能把 `0`、`+0`、`0q`、`0r` 统一解释为空集。未支持的特殊定义保持不透明并给出说明，不为了覆盖它而新增复杂的专门模型库。

## 11. #abs 同时支持项和公式

### 11.1 项

```text
#abs(t,D) -> (D(t) & #sat(t,D)=t)
```

这里外部 t 保持外部含义。是否成立由玩家证明；不能因为内部项已经有一个定义就自动推出它等于外部 t。

该形式不要求原定义关系唯一：它比较的是两个已经选定的对象值，不是宣称所有可能的选择都相同。

### 11.2 公式

```text
#abs(A,D) -> (G_D(A) > (A <> #sat(A,D)))
```

G_D(A) 是 A 的对象自由变量属于 D 的条件合取。没有对象自由变量时直接输出 `A<>#sat(A,D)`。

仅作为域固定参数出现的变量不因此追加域条件；若同名变量也出现在 A 的普通对象位置，则仍需相应条件。

展开只是生成等价含义的新定理或证明目标，不等于证明了绝对性。使用绝对性化简仍需该绝对性已成立，以及它依赖的前提。

## 12. 结构归纳：复用 ##matchrp，不建立独立 P[] 语言

### 12.1 模板实例化

玩家提供普通公式模板 T，其中使用一个保留的元层公式槽（实现示意为 `#slot`）。填入 A 得到 T[A]。

可复用 `##matchrp` 的模式匹配替换辅助函数实现这个过程，但：

- 当前代码没有通用的 `##matchrp` 求值引擎，需要把有关辅助逻辑整理成可调用函数；
- 使用精确的保留槽匹配，不能将单个普通 `$F` 当成“匹配任何子树”的模式到处替换；
- 模板替换必须做变量捕获检查；
- `#slot` 仅为元规则输入中的占位符，不成为新的普通一阶谓词。

因此不要求用户学习一套独立的 P[] DSL；P[A] 在本文中只作说明记号。

### 12.2 新元规则

增加公式结构归纳元规则，输入：模板 T、原子属于/相等两种情形的规则、否定/蕴含/全称三个构造步骤的规则，以及目标公式或待保留的公式模板。

统一入口为 `mfinduct`，工具栏增加 `结构归纳(mfinduct)` 按钮，进入上述分步输入流程。规则参数允许通过点击已有规则选择；生成成果以后，沿用现有规则/元规则的点击执行机制，不额外发明一个只有命令行可用的实例化命令。

基本语言为 `x@y`、`x=y`、`~`、`>`、`V`。x/y 可相同。其他连接词通过允许的展开过程纳入；具体额外符号未覆盖时拒绝，不暗中视作原子。

在结构递归中用模板替换辅助计算 T[A]，再用玩家提供的已验证规则组合证明。原子规则和构造步骤必须通用；量词分支保留新鲜性与不自由出现条件，共同前提不能暗中增强。

`##matchrp` 能省去模板实例化的另一套实现，但不能代替结构递归，也不能把“字符串能替换”当成归纳步骤已经证明。

保存成果仍是一条可实例化的元规则/带结构归纳步骤的推理规则，而不是独立的“模型证书对象数据库”。用户可以继续将实际生成的证明录制为普通宏。

## 13. 满足 ZF/ZFC：只保留可调用规则，不做记录系统

不增加模型面板、模型列表、模型是否完成的存档字段、自动满足状态或徽章。

玩家证明的有限公理、分离/替换模式和其他结果全部是现有规则表中的定理、推理宏或元规则。最终希望只有一个调用入口时，可组合成一条“ZF/ZFC 公理相对化模式”的元规则：输入公理名称及模式参数，输出该公理实例在 D 下成立的推理规则，保留共同假设。

如果玩家已经在规则系统中证明了足够通用的分离/替换模式，也可以将有限公理和两个模式实例组成一个带公式参数的普通推理规则。

必须区分：

- 分离/替换模式需要覆盖所有允许公式，几个实例不够；
- 不能把结果简写成无约束的 `Γ ⊢ #sat($A,D)`，否则它会错误地断言任意公式在 D 中成立；
- 若用单个入口接受任意公理实例，需要由元规则在运行时核验其确实属于 ZF/ZFC 公理模式，而不是增加对象层的统一满足谓词。

否定某个公理实例也只保存为普通定理/推理规则。本功能不替玩家构造任何具体模型或模型论结论。

## 18. 可靠性与验收要点

### 18.1 可靠性目标与实施范围

目标是：在原推理系统及其既有定义机制可靠的前提下，新增玩法不引入推出 `false` 的途径。不能无条件承诺原系统或 ZFC 的一致性，也不能阻止玩家从明确假设的矛盾推出 `false`；必须保证这些假设完整保留，不被误记为无前提定理。

本次及按本文实现时的交付约束：不实际操作游戏，不运行测试，不添加或打包测试代码。以下要求是设计约束、源码静态审查要点及实现必须执行的运行时核验，不是要求自动执行的测试任务。没有运行验证的内容不得声称已经通过运行验证。

### 18.2 核心判定与拒绝策略

- UI、按钮、命令和宏仅提交操作请求；是否可追加定理由推理核心统一决定。禁止按钮直接往定理列表写入未经核验的结论。
- 每条新规则须说明其对应的外层公式/项含义，以及为何在保留前提后保持可推导性；可展开操作采用明确的有限白名单，不依据字符串前缀、显示文本或用户声明放行。
- 语法必须完整解析并消费全部输入；拒绝尾随未解析内容、类别不确定、未绑定模板、歧义定义、缺少解释及不支持的结构。失败不得退化为“当作原子”“默认相等”或“忽略条件”。
- 核验成功后才原子性提交定义和证明步骤；失败、取消、递归超限均不留下可引用的新结论或符号定义。
- 每步准确记录未解除假设、依赖规则及侧条件。局部假设、特征变量、临时模板绑定不能泄漏到全局结论；假设的解除只允许现有合法规则执行。

### 18.3 定义解释及相对化的证明义务

引入新符号前，必须静态论证新增解释约定可由旧语言中的定义扩张支持。不能把“公式看起来是相对化”作为新公理的依据。常量/函数沿用原 `mc/mf` 机制及其可靠性前提，不额外宣称它们无需任何元理论条件。

- 原定义必须来自可核验的定义引入步骤，且其 AST 符合支持的模式；不能仅凭 `df/dv/dc` 名称或一个形似定义的任意定理认证其来源。所需来源使用普通证明依赖保存，无需新增模型注册表。
- 定义体不得包含新符号自身或构成间接循环；形式参数须互异且类别正确，所有自由变量都有显式参数或保留条件。参数化选择必须对全部参数按原定义规则引入，不从逐个实例的存在性擅自删去依赖。
- 相同原符号和论域参数模板的解释保持稳定；域参数、原项参数和别名的每个参数位置都须核对。新鲜性覆盖已有符号和证明引用，不能通过重名、删除再建或加载改变旧证明的含义。无法唯一识别已有解释时拒绝。
- `#sat(f(t),D)` 连接到内部别名时，其对象实参使用已解释的项；域固定参数保持外层含义。定义体先相对化再自由代入内部值，不能对内部别名再次解释。
- 选择定义产生的是带存在前提的性质。没有存在性/闭包证明，不能断言所选值属于 D 或满足定义关系；空论域也不能自动获得内部常量。需要标准非空模型语义的结论必须显式保留 `Ex:D(x)`。
- 未取得内部存在性时，项可作为一个已定义的外层总项保持不透明，但不能据此宣称构成标准内部结构。相对化基本集合论公式与满足扩充函数语言的模型须区分所需闭包前提。
- 不自动继承外层公理、定理、函数闭包或绝对性；每项需要独立证明。非唯一选择本身不增加唯一性要求，也不允许两次选择被无依据认作相同值。

### 18.4 展开、嵌套与替换

直接展开必须验证整条源公式在其实际上下文中保持含义，不能只验证被替换子式在外层等价。只有经核验、兼容该上下文解释的定义转换才能穿过外层 `#sat/#abs`；普通已证明的等价或等式仍按原逻辑规则及其前提使用，不能借展开模式跨模型搬运。

对嵌套转换必须给出有限的递归解释，外层域也作用于内层展开后出现的量词及域谓词含义，不能简单把外层分发到未解释节点的参数。尚不能给出该情形的严格转换时拒绝该次行动，保留节点不透明；不以支持嵌套为由跳过核验。

统一使用避免捕获的 AST 替换：量词绑定变量、域固定参数、定义参数及结构归纳特征变量分别处理，必要时先作 α 改名。自由变量计算须查看不透明节点内部；`#abs` 的保护条件不能漏掉对象变量，也不能把域参数误绑定。涉及 `#abs` 的上下文改写还须核对保护条件变化，不能仅凭子式等价删改条件。

### 18.5 结构归纳的严格范围

- 先声明归纳覆盖的语法类别。仅用变量原子 `x@y`、`x=y` 和三种基本构造的归纳，只能覆盖对应的纯关系语言；含函数项、常量、额外谓词或模型操作的公式必须先有可靠的消去解释，或补齐并证明对应分支，否则拒绝。不能把任意项默认为变量。
- 原子分支必须对所有允许变量及其同一/不同情形成立；构造分支应为通用规则。否定步骤只能从该子式的归纳假设推出对应目标；蕴含步骤只能使用两个子式的归纳假设及共同前提，不能偷用当前目标或其他未获证实例。
- 全称分支明确区分语法元变量与对象变量，核验特征变量新鲜性、自由出现限制及共同前提。任意依赖具体变量、特定谓词、列表长度或公式形状的额外条件必须保留或拒绝该分支，不能冒充无条件通用步骤。
- 对具体公式按严格子式递归组合已验证的证明；对保留公式模板的成果，保存为受限元规则，实例化时仍核验语法范围和全部侧条件。不能只匹配到结论形状就登记为普通无前提规则。
- `#slot` 是有类别的精确元槽，列表槽只能位于许可参数位置。模板槽不能充当一阶量词变量、隐藏额外假设或令匹配替换器执行任意新推理。

### 18.6 保存恢复及审查要求

保存的结果文本不是证明依据。恢复或宏重放时，新步骤必须通过同一核心检查，重查依赖、解释来源、目标 AST 路径及侧条件；不能将读取到的结论直接视为系统赠送的公理。不兼容、缺依赖或无法核验的步骤应标为不可用，不允许继续参与可靠推理。这不承诺防范玩家任意修改程序本身。

实现审查须逐项说明：新增受信任入口、每个入口的输入检查、输出规则的证明依据、假设传递方式、定义扩张条件、失败回滚和保存恢复方式。若某处无法完成这份论证，应缩小该操作的支持范围，而不是放宽可靠性检查。无需为此增加游戏内容、独立证书数据库或测试文件。
