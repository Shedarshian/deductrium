# 深层定理依赖的惰性求值

基线：本地 main，提交 62c2a81。实现分支：codex/lazy-theorem-evaluation。

本方案针对通用的宏依赖、元规则变换与证明展开，不针对任何具体定理或数学对象。

## 问题与处理原则

普通 deduct 原本已能直接使用规则签名，但注册宏、收集 tempvars 和生成复合元规则时，会提前构造依赖的证明。依赖嵌套增加后，这些隐式求值会放大内存占用。深度展开还依赖 JS 调用栈，显式输出量也可能指数增长。

实现将签名、证明来源与显式展开分开；按名称保留子规则引用，访问当前层时才加载证明体。推理匹配、替换参数顺序、断言与元规则适用性继续由现有内核处理。

## 数据与入口

在 src/fs/formalsystem.ts 中，Deduction 保留现有签名字段，并增加可选 ProofSource：

- length：证明是否有步骤的元数据；变换配方在物化前使用非零标记。
- dependencies：直接依赖名称，用于分析、删除及重命名，不需要加载 AST。
- load：显式构造当前层证明体。
- serialize：对存档中的紧凑证明数据直接序列化，避免保存时物化证明。

isMacro 根据 steps 或 proof 判定宏，不能把“尚未物化”当成公理。
getProofSteps 是明确的求值入口，不使用隐式 getter。

## 已实施的代码修改

### 注册与存档

src/fs/savesparser.ts 在读档时解析签名并迁移旧规则名，保留紧凑步骤字符串；实际使用证明体时才解析替换 AST。保存用户宏保持原格式，可直接保存紧凑来源。

addMacro 与 findLocalNamesInDeductionStep 不再为收集局部变量元数据生成引用规则。现有显式 tempvars 数据仍保留；展开时继续使用原有替换、局部名避让与断言检查。

### 元规则

条件化 c、条件概括 v、演绎 >、逆演绎 <、概括 u 和特称 e 对支持这些变换的规则先生成规范化签名和证明配方。可适用性分析迭代访问依赖引用，以已登记的原子规则和已有推导为依据，不构造派生证明体。未知的带条件原子规则仍走原检查路径，不能直接视为支持变换。

证明配方调用原有变换算法生成当前层，子变换仍是惰性引用；物化完成后检查签名一致性。公理概括 q 的限制继续保留，未展开的宏不会因此被当作公理。

概括 u 的签名使用原算法相同的假设归一化与匹配表传播不自由断言；不能简单将原规则重新应用到包装后的假设上，否则会引入不同的匹配约束。演绎/逆演绎的抵消规则、条件数量检查及对不支持的原子规则的限制继续保留。

组合元规则保留原有的签名构造与检查算法，引用上述一元元规则时不再为了获得签名而构造其证明，并与同一求值预算共享资源限制。

演绎变换先计算各步骤是否依赖被消去的假设，替代“复制 proposition 数组、试探推导、失败回滚”的过程。

### 展开

普通应用及 partialTest 仅读签名；callback 形式的 inlineMode 也先确定最终模式，再决定是否加载证明体。

inline 只展开当前层。deep 使用生成器与显式工作栈，不递归调用 deduct。负条件索引通过当前层的输出索引表解析，避免逐步累加偏移。展开后检查最终结论与规则签名一致。

循环证明依赖给出明确错误。原有递归元规则构造和规则名解析也受深度限制，避免无限递归。

### 预算与状态恢复

src/fs/evaluation.ts 提供共享的同步求值预算。默认限制：50,000 次操作、2,000,000 个解析/克隆 AST 计数、约 3 秒求值时间、128 层递归构造。深层宏展开使用显式栈，不受该递归构造层数限制。

预算在嵌套生成、解析、克隆及展开之间共享，不为每个子规则重新开始。循环、预算耗尽或推理失败会恢复本次操作前的 propositions、规则表与解锁状态。内联更新后续索引时创建新记录，保留预览快照。

这些限制用于中止无法容纳的显式输出；惰性求值不能让任意规模的完整证明输出变得有限。

### 缓存与界面

解析后的证明缓存最多 128 条、估算 100,000 个节点/索引；派生规则缓存最多 512 条、估算 100,000 个节点/索引。过大的证明体可使用但不保留在证明缓存中。公理、内置规则及用户记录的宏保留在权威规则表中。

删除、重命名及符号定义变化会失效派生缓存；重命名需要修改用户宏引用时，发布新条目。缓存淘汰后按规则名称重新生成。

src/fs/gui.ts 的列表宏标记只读元数据。src/fs/cmd.ts 中点击、筛选及删除等读取路径能够重新查询被淘汰的派生规则，避免依赖缓存永久存在。

## 验证方式

按照 tsconfig.json 编译 TypeScript；同时提交对应 js 文件和 source map。仓库使用已提交的 JS 运行网页。

运行回归：node tests/lazy-evaluation.mjs。无需安装测试依赖，使用 Node 内置 test 模块。历史对照从 Git 提交 62c2a81 只读提取 JS 到临时目录，结束后清理。

覆盖内容：

- 4000 层宏的加载、普通应用、录制和保存不加载被引用证明体。
- 4000 层深度展开不依赖 JS 递归栈；一层展开保留子宏引用。
- 循环、输出膨胀及预算错误能够恢复原状态，下一次正常操作仍可完成。
- 公理概括、非法元规则及未知条件原子的原有限制。
- 删除、重命名、缓存淘汰与重新生成。
- 全部 195 个内置宏的 c/v 配方，共 390 种变换的物化签名检查。
- 多层演绎再多层概括的依赖链：底层证明体设为读取即报错，获取外层规则及展开外层一层仍能完成。
- 演绎、逆演绎、概括和特称元规则仅查询签名时，不读取输入宏的证明体。
- 与旧实现对照小证明的签名、替换参数顺序、类型、逐层展开及最终结论，包含量词和不自由断言。
- 内联后续步骤索引正确，并保留旧预览记录。

压力测试是通用合成依赖链，证明了求值与展开路径的行为；不将合成结果当作所有真实存档的性能保证。

## 后续修正

首版 a8f2310 只延迟了 c/v 的构造，演绎等入口仍在获取签名时调用 getProofSteps；这使“只展开外层一层”也可能在准备子规则时提前求值多层证明。后续补丁统一这些一元元规则的惰性签名入口，并增加禁止读取后代证明体的回归测试。资源预算保持原值。
